# CodeArts: v2 regression contract and v1.6.5 oracle procedure

## Status and provenance

**Current status: the v2 regression contract is complete; the selected
CodeArts v1.6.5 oracle slice is recorded, and the remaining parity delta is
documented.**

The selected CodeArts outputs (`codearts_models`, `codearts_chat`,
`codearts_chat_stream`, `codearts_accounts`, `codearts_overview`,
`codearts_checkin`, `codearts_credits_refresh`, `codearts_models_refresh`) are
committed in `tests/oracle/recorded/v1.6.5/`. They were captured from the v1
fake upstream with synthetic account `u1`; see that directory's
`PROVENANCE.md` for hashes, commands, and the exact v2 differences. The
deterministic CodeArts failure matrix (429, 401, credit-exhausted 400,
concurrency 400) is committed in
`tests/oracle/recorded/v1.6.5-failures/codearts/` and matches v2 5/5 exactly;
see the parent `PROVENANCE.md` and `V2-DELTA.txt`. The `codearts_*` fixtures
below remain v2 regression goldens, not oracle output.

The CodeArts fixtures in `tests/contract/testdata/codearts_*.golden.json` are
**v2 regression goldens**, generated by the local fake CodeArts upstream through
the real `codearts.New(store)` provider and the real `api.NewServer`. They are
**not outputs captured from a v1.6.5 oracle run**.

The general `tests/oracle/README.md` documents the Raccoon oracle procedure.
This file is the CodeArts-specific procedure and fixture provenance.

- They lock down the v2 foundation's scoped CodeArts behavior: health, models,
  chat non-stream/SSE (text and tool calls), overview, check-in, credits refresh,
  models refresh, disabled/error envelopes, concurrency retry/failover, and
  credit-exhausted failover.
- `NormalizeJSON` and `NormalizeSSE` compare the complete scoped payloads. No
  key projection is used: an extra or missing stable field fails. The only
  value placeholders are documented dynamic values (`base_url`,
  `token_remaining`, every time-of-day credit multiplier (models whose peak
  and off-peak rates differ), timestamps, generated IDs).
- The selected v1.6.5 CodeArts payloads are now committed under
  `tests/oracle/recorded/v1.6.5/`. They confirm the chat/models/account shapes;
  the parity-fix candidate now emits the v1 `catalog` block and
  `elapsed_ms`/`first_chunk_at` chat fields. The remaining differences are two
  additive v2 fields (`stats.limited`, `credits_refresh.accounts[]`). Full
  oracle replacement of every `codearts_*` regression fixture is still pending.

The procedure below is how to record the real oracle later and validate or
replace these scoped fixtures.

## Final-review parity fixes and exclusions

The final review aligned these behaviors with v1.6.5: live settings on chat
entry, per-read `stream_timeout_seconds`, clean-EOF terminal synthesis, 502 for
chat unavailable/no-account/network, three concurrency attempts with 2s/4s
backoff, ordinary 5xx errors as non-soft, unknown-secret callback rejection,
signed OAuth identity enrichment, access-key redaction, redirect-blocking
signed transports, and fresh model discovery after invalidation. See
`tests/contract/testdata/PROVENANCE.md` for the audit list.

The following differences are intentional and must **not** be recorded as v1
oracle output:

- v2 sanitizes every non-`[A-Za-z0-9._-]` auth-path character (v1 only replaced
  path separators), and still verifies the embedded UID before overwrite.
- v2 refuses HTTP redirects on signed upstream requests; v1's urllib client
  could follow them.
- v1's `drop_missing_bindings` runs only from its panel proxy-slot save route.
  That route is outside the v2 CodeArts surface; v2 preserves the binding and
  resolves a missing/disabled slot to direct like `apply_proxy_slots`.
- v2 records v1's `elapsed_ms`/`first_chunk_at` chat fields and the models
  `catalog` block. `elapsed_ms` is a variable wall-clock duration and normalizes
  to `<duration>`; the fields themselves are part of the contract.

## Read-only rules

- The source tree `/root/opencode/mix2api` is **read-only**. Never edit it.
- Copy the v1.6.5 tree with `git archive` into `tests/oracle/v1.6.5`.
  `tests/oracle/.gitignore` excludes that directory and Python caches, so the
  copy cannot be committed.
- Patch only the copied tree if a test harness hardcodes a host. v1.6.5 already
  reads `WB_CODEARTS_*` environment variables, so the normal path needs no
  source edit.
- Verify `git -C /root/opencode/mix2api status --short` is empty before and
  after recording.

## 2. Start the fake upstream and point the copy at it

The v1.6.5 fake lives in `app/tests/_fake_codearts.py` and serves OAuth token,
chat SSE, agent/builtin/benefit discovery, statistics, and check-in delivery/
claim/confirm. It uses no real network and no real account.

`wb_codearts` reads these variables at import time, so the copied gateway can
be pointed at the fake purely through the environment:

- `WB_CODEARTS_SNAP_HOST` (chat/builtin/agent/check-in)
- `WB_CODEARTS_SNAP_MANAGER` (statistics plugin)
- `WB_CODEARTS_BENEFIT_HOST` (benefit discovery/claim)
- `WB_CODEARTS_STS_HOST` (token refresh)
- `WB_CODEARTS_PORTAL_HOST` (OAuth portal)

```bash
TMP=$(mktemp -d)
cat > "$TMP/fake_codearts.py" <<'PY'
import json
import os
import sys
import time

ROOT = os.getcwd()
sys.path.insert(0, os.path.join(ROOT, "tests/oracle/v1.6.5/app/tests"))

from _fake_codearts import start_server  # noqa: E402

server, base, state = start_server()
with open(os.environ["FAKE_INFO"], "w", encoding="utf-8") as fh:
    json.dump({
        "base": base,
        "token": state.token,                 # cloud_dragon_token
        "refresh_token": state.refresh_token,
        "access_key": state.api_key,
        "secret_key": state.secret_key,
        "uid": state.user_id,
        "user_name": state.user_name,
        "domain_id": state.domain_id,
    }, fh)
print(base, flush=True)

# start_server() serves on a daemon thread; stay in the foreground so the
# process is not reaped while the gateway is running.
while True:
    time.sleep(1)
PY

FAKE_INFO="$TMP/fake.json" python3 "$TMP/fake_codearts.py" > "$TMP/fake.log" 2>&1 &
FAKE_PID=$!
GATEWAY_PID=""
trap 'kill "$GATEWAY_PID" "$FAKE_PID" 2>/dev/null || true' EXIT
for _ in $(seq 1 100); do
  [ -s "$TMP/fake.json" ] && break
  sleep 0.1
done
test -s "$TMP/fake.json"
BASE=$(python3 -c 'import json,sys; print(json.load(open(sys.argv[1]))["base"])' "$TMP/fake.json")
printf 'fake upstream: %s\n' "$BASE"
```

The fake's default behavior is the semantic v1 stream: role, one `你好` text
delta, `finish_reason=stop`, usage `3/2/5`, and `[DONE]`. Its model catalogue
comes from `FakeState.builtin`, `agent_models`, and `benefit_models`; the check-in

## 5. Record the endpoints

```bash
mkdir -p "$TMP/recorded"
V1=http://127.0.0.1:18766

curl -fsS "$V1/health?force=1" -o "$TMP/recorded/health.v1.json"
curl -fsS "$V1/v1/models?realm=codearts" -o "$TMP/recorded/models.v1.json"

curl -fsS -H 'Content-Type: application/json' \
  --data '{"model":"GLM-5.2","messages":[{"role":"user","content":"hello"}],"stream":false}' \
  "$V1/v1/chat/completions?realm=codearts" -o "$TMP/recorded/chat_nonstream.v1.json"

curl -fsS -N -H 'Content-Type: application/json' \
  --data '{"model":"GLM-5.2","messages":[{"role":"user","content":"hello"}],"stream":true}' \
  "$V1/v1/chat/completions?realm=codearts" -o "$TMP/recorded/chat_stream.v1.sse"

curl -fsS -H "X-Panel-Token: $PANEL" \
  "$V1/codearts/overview?force=1" -o "$TMP/recorded/overview.v1.json"

curl -fsS -X POST -H 'Content-Type: application/json' -H "X-Panel-Token: $PANEL" \
  --data '{"uid":"u1"}' "$V1/codearts/accounts/checkin" \
  -o "$TMP/recorded/checkin.v1.json"

curl -fsS -X POST -H 'Content-Type: application/json' -H "X-Panel-Token: $PANEL" \
  --data '{}' "$V1/codearts/credits/refresh" \
  -o "$TMP/recorded/credits_refresh.v1.json"

curl -fsS -X POST -H 'Content-Type: application/json' -H "X-Panel-Token: $PANEL" \
  --data '{}' "$V1/codearts/models/refresh" \
  -o "$TMP/recorded/models_refresh.v1.json"
```

Useful error/edge recordings, each from a fresh gateway state:

- **Disabled realm**: stop the gateway, edit
  `"$TMP/accounts/settings.json"` to `"enabled": false`, restart with the same
  environment, then record `GET /codearts/overview`,
  `GET /v1/models?realm=codearts`, and one chat request. v1 returns 503 for
  overview/models and a readable 400 for chat.
- **Concurrency**: configure `FakeState.chat_error` in the fake process or use
  `_test_codearts_native.py`'s fake hooks; the v1 contract is a 400 concurrency
  message retried once, then failover/429.
- **Credit exhausted**: set `FakeState.credit_error_once = True` (or make every
  account fail) and record the failover response or the readable 400.
- **Unknown route/error**: `GET /codearts/not-a-route` and an upstream
  validation 400 (`{"error_msg":"request param is invalid"}`).

Record raw bytes first; do not hand-edit IDs or timestamps.

## 6. Normalize and compare

`tests/contract/normalize.go` is the single normalizer. Compare only the
semantic fields the scoped fixture needs; never project the v2 payload onto a
hand-picked subset. For CodeArts specifically:

- `created`, `fetched_at`, `expires_at`, `until`, `checked_at`, and date-shaped
  values become `<timestamp>`. v1's `expires_at`/`until` spelling is a local
  wire time without a zone, so it must be recognized as a timestamp (the
  normalizer supports this). `until` is value-checked: only strings that parse
  as timestamps are replaced, so a semantic non-time value survives.
- `base_url` becomes `<upstream>` after replacing the fake URL; the port changes
  per run.
- `accounts[].token_remaining` is a per-second countdown; use `<duration>`.
- Every model whose `credits_peak` differs from `credits_offpeak` has a
  time-of-day `credits` multiplier. In the current catalogue that is
  `DeepSeek-V4.1-Flash` (`x0.18` peak / `x0.09` off-peak) and
  `DeepSeek-V4.1-Flash-1017` (`x0.18` / `x0.12`). Compare a
  `<time_of_day_credits>` placeholder while asserting the live value is one of
  the model's two published rates; `credits_peak`, `credits_offpeak`, and
  `credits_note` stay fully compared.
- Generated chat IDs (`chatcmpl-*`, `call_*`, request/session/trace IDs) become
  `<dynamic>` only in identifier fields. Model IDs and account IDs are semantic
  and must survive.
- SSE normalization ignores chunk boundaries, comments, and keepalives; it
  merges role/content/finish/tool-call/usage and records `[DONE]`.

Formerly v1-only fields now emitted by v2:

- v1 non-stream chat `elapsed_ms` and `first_chunk_at` (the duration value is
  normalized).
- v1 `/v1/models?realm=codearts` top-level `catalog` block.
- v1's panel/media/key-readiness health blocks are restored on `/health`; the
  neutral `providers` map remains additive.

Do not fabricate values into a v2 golden. Stable fields are still compared in
full; only inherently variable durations/timestamps use placeholders.

## 7. Record and review

1. Normalize the recorded v1 payloads with `NormalizeJSON`/`NormalizeSSE`
   (using a throwaway Go test or a small in-package harness).
2. Compare the normalized v1 semantic values with the existing
   `codearts_*` regression fixtures.
3. If a difference is intentional v2 scope, document it above and in
   `tests/contract/testdata/PROVENANCE.md`.
4. If a difference is a provider/API bug, fix it with a failing test before
   updating the fixture.
5. Replace a fixture only after review. The v2 regression suite must still pass:

```bash
go test ./tests/contract -run TestCodeArts -count=1
go test ./...
go test -race ./...
go vet ./...
gofmt -l .
```

Before committing, prove the original tree is untouched and the copy is still
ignored:

```bash
git -C /root/opencode/mix2api status --short
git status --short
git check-ignore tests/oracle/v1.6.5
```

No real account or real network is used at any point.

## Regenerating the current v2 regression fixtures

The committed suite reads fixtures only; it never writes them. To refresh the
v2 regression fixtures, add a temporary in-package test that constructs
`newCodeArtsContractFixture`, drives the same real endpoints, and writes
`NormalizeJSON`/`NormalizeSSE` output into `tests/contract/testdata`. Delete the
temporary dump test before committing, and review every changed fixture as a
semantic change. This is how the current fixtures were produced; it is
independent of the v1.6.5 oracle procedure above.
