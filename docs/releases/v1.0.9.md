# mix2api v1.0.9

v1.0.8 之后的补丁版：撤销 `YYLS/` 命名空间，CodeArts 模型重新使用原版名字。

## 这个版本做了什么

- **模型名回到原版**：CodeArts `/v1/models` 重新返回 `GLM-5.2`、`Qwen3-VL-235B`、`deepseek-v4.1-flash` 等原版 ID，不再加 `YYLS/` 前缀。
- **按出口选择，不按模型名区分**：当前网关一次只走一个出口，CodeArts 由 API Key 绑定或面板默认出口选择；裸模型名即可。`/v1/models?realm=all` 不再合并 CodeArts，避免和 WorkBuddy 同名模型冲突。
- **以后多出口再加前缀**：等需要同时服务多个出口时，再引入 `provider/` 前缀做区分；现在不提前加。
- **其余能力保留**：图片、工具调用、推理档位、参数透传、代理槽、自动签到、30 分钟保活、账号备注/任务开关/测试/重新登录/刷新积分、活动历史都不变。

## 升级

- 直接替换镜像或代码即可，无数据迁移；默认端口仍是 `58675`。
- 客户端如果缓存了 `YYLS/...` 旧 ID，刷新一次 `/v1/models`；旧前缀不再作为路由别名接受。
- 需要走 CodeArts 时，把 Key 绑定到 `codearts`，或把面板默认出口切到 CodeArts。

## 验证

- 243 个测试套件全过。
- `/v1/models?realm=codearts` 返回裸模型 ID。
- CodeArts 绑定的 Key 直接请求 `GLM-5.2` 正常；图片、工具、推理、Responses、Anthropic Messages 回归通过。

## Docker 镜像

已发布到 GitHub Container Registry，支持 `linux/amd64` 与 `linux/arm64`：

```bash
docker pull ghcr.io/ayeaaaa/mix2api:v1.0.9
docker pull ghcr.io/ayeaaaa/mix2api:latest
```

直接运行：

```bash
docker run -d --name mix2api -p 58675:58675 \
  -v "$PWD/data/accounts:/app/accounts" \
  -v "$PWD/data/usage:/app/usage" \
  ghcr.io/ayeaaaa/mix2api:v1.0.9
```

或用本包里的 `deploy/docker-compose.image.yml`：

```bash
cd deploy
docker compose -f docker-compose.image.yml up -d
```

## English summary

`mix2api` v1.0.9 removes the `YYLS/` namespace and returns to original CodeArts model ids. The active exit is selected by the API key or panel default; `/v1/models?realm=all` no longer merges CodeArts, avoiding collisions with same-named WorkBuddy models. A `provider/` prefix can be introduced later when multiple exits are served simultaneously. All other features (images, tools, reasoning levels, parameter passthrough, proxy slots, auto check-in, 30-minute keepalive, account actions, activity history) are unchanged. The multi-arch image is published as `ghcr.io/ayeaaaa/mix2api:v1.0.9` and `:latest`.
