# mix2api v1.0.0

首个发行版：把 **WorkBuddy 国际版**、**WorkBuddy 国内版** 和 **华为云 CodeArts** 收进一个 Python 单进程网关，一个看板、一套 API Key。

## 项目由来

本项目是 [workbuddy2api-hub](https://github.com/ardeyouxipianyi/workbuddy2api-hub)（MIT）和 [codearts2api](https://github.com/HITZY2002/codearts2api)（MIT）的整合分支。

- wb-hub 原本只有 WorkBuddy 国际版 / 国内版两个出口；codearts2api 是独立的 Go 服务，自己管华为云账号池。
- 目标：让 wb-hub 的出口开关多一个 `CodeArts`，三个上游共用一个地址、一个看板、一套 Key。
- 先做过「hub + 独立 codearts2api」的代理版；确认要单进程后，把 CodeArts 的 OAuth、token 续期、模型发现、聊天 SSE、签到和积分查询移植进 Python，最终只运行 `app/` 一个服务。
- `reference/codearts2api/` 只保留 Go 源码作协议参考，不参与构建和运行。

## 这个版本做了什么

- **单进程 CodeArts 客户端**：OAuth2 PKCE + DPoP、refresh_token 续期、账号池/并发/冷却、模型发现（agent-center / builtin / 限时福利）、聊天 SSE、签到、积分余额。
- **纯标准库密码学**：P-256 ECDSA、DPoP JWT、PKCE、华为云 `SDK-HMAC-SHA256`；ECDSA 与 HMAC 都用 Go 侧向量对拍。
- **看板**：第三张 CodeArts 出口卡片、三出口切换、CodeArts 账号表（OAuth 添加 / 启停 / 清冷却 / 签到 / 删除）、设置页、积分余额与已用/总额、模型描述。
- **协议与用量**：`/v1/chat/completions`、`/v1/responses`、Anthropic Messages 统一路由；CodeArts 用量记 `realm=codearts`，不按 WorkBuddy 价目表计价。
- **部署**：单服务 compose，默认端口 `58675`；`make build / up / test / logs`。
- **测试**：243 个 hub 套件全过；CodeArts 链路用本机假华为云上游覆盖，密码学有 Go 对照向量。
- **测试中修掉的问题**：OAuth 回调缺 `user_id`、上游 3 并发会话限制、签到状态重启丢失、积分显示、价格回退等。

## 快速开始

```bash
cd deploy
docker compose up -d --build
```

打开 `http://127.0.0.1:58675/`，默认面板密码 `admin`（登录后立刻改）。  
进「设置 → CodeArts 接入」勾选启用，保存；到「账号」页切 CodeArts，点「+ 添加账号 (OAuth)」。

## 包含内容

- `mix2api-1.0.0-deploy.zip`：`app/`、`deploy/`、`docs/`、根 README/LICENSE/UPSTREAM/Makefile；不含运行时 `data/`、账号凭据和测试缓存。
- GitHub 自动生成的 Source code 包含完整仓库（含 `reference/codearts2api/`）。

## 已知限制

- CodeArts 单账号最多 **3 个活跃会话**；默认单账号并发为 1，并对上游 400 并发限制做短暂重试。大量不同会话建议增加账号或复用 `conversation_id`。
- 积分显示的是**账户级**剩余/总额/已用；聊天接口不返回单次请求的积分扣减，所以最近请求表的积分列对 CodeArts 显示 0.00，估算价格显示 `—`。
- 视觉模型（Qwen3-VL、Kimi-VL）在目录里存在，但当前 CodeArts 路径只透传文本，图片输入会被压平丢弃。
- 本项目仅用于协议学习与个人自用；账号风控、限流、封禁风险由使用者自行承担。请优先使用官方客户端，不要使用主账号，不要共享或转售账号。

## English summary

`mix2api` is a single-process, OpenAI-compatible gateway that serves WorkBuddy Global, WorkBuddy China and Huawei Cloud CodeArts from one Python service. CodeArts OAuth (PKCE + DPoP), token renewal, the account pool, model discovery, the chat SSE stream, check-in and the credit balance all run inside the process; the Go `codearts2api` is kept only as a protocol reference. The release includes the app, a single-service compose file, docs and tests.
