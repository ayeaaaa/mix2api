# mix2api v1.1.3

安全补丁：CodeArts 账号表的 UID 不再直接进入 inline `onclick` 的 JavaScript 字符串。

## 这个版本做了什么

- **修复 CodeArts 面板 UID 注入风险**：`renderCodeartsAccounts()` 以前把 `escapeHtml(uid)` 拼进单引号 `onclick` 处理器。HTML 转义不处理单引号，也不能保护 JavaScript 字符串上下文。现在 UID 先收敛成安全字符集 `[A-Za-z0-9_.@-]`，再用于所有 inline 操作按钮；页面显示仍使用 HTML 转义后的原始 UID。
- **同类位置一并处理**：版本回退按钮的备份参数也改成安全字符集后再拼入 `onclick`。
- **回归测试**：新增恶意 UID（含单引号与 `onmouseover`）用例，确认不会跳出 `onclick` 字符串，处理器只收到收敛后的安全 id。
- 正常 CodeArts UID 是 UUID/hex，行为不变。

## 升级

- 直接替换镜像或代码即可，无数据迁移；默认端口仍是 `58675`。
- 默认 `/` 新面板，`/classic` 旧面板。
- 客户端 API 地址、Key、模型 ID 不变。

## 验证

- 246 个测试套件全过。
- CodeArts 账号表、版本回退按钮的 inline handler 均有安全字符集断言。

## English summary

`mix2api` v1.1.3 fixes a CodeArts panel injection risk: account UIDs were HTML-escaped but then embedded in single-quoted inline `onclick` JavaScript strings, where HTML escaping does not protect the string context. UIDs are now reduced to a safe `[A-Za-z0-9_.@-]` charset before use in handlers, while display still uses the escaped original. The version-rollback handler received the same treatment, and a malicious-UID regression test was added. 246 test suites pass.
