# mix2api v1.0.3

v1.0.2 之后的补丁版：CodeArts 视觉模型支持图片输入。

## 这个版本做了什么

- **CodeArts 图片输入**：视觉模型不再把 `image_url` 内容分片压成纯文本。OpenAI `image_url`（对象或字符串）、Responses `input_image`、Anthropic `image`（base64 / URL）都会归一化成 CodeArts 接受的 `image_url` 内容分片。
- **文本-only 不变**：没有图片的消息仍然压成纯字符串，保持原有线上格式，不影响文本模型和旧客户端。
- **三种协议统一**：`/v1/chat/completions`、`/v1/responses` 和 Anthropic Messages 的图片块最终都走同一条 CodeArts 图片路径。
- **data URL 实测**：64×64 数字图、512×512 噪声图（约 1 MB data URL）都能被上游接受；Qwen3-VL-235B 与 kimi-k2.6-vl 都能正确读出图中的两位数。

## 升级

- 直接替换镜像或代码即可，无数据迁移；默认端口仍是 `58675`。
- 图片能力取决于所选模型；文本模型收到图片时仍可能由上游拒绝。
- 远程图片 URL 会原样透传，能否抓取取决于上游；需要稳定时建议客户端发送 base64 data URL。
- 图片过大可能触发上游请求体限制；网关自身的单请求体上限仍按设置页/环境变量执行。

## 验证

- 243 个测试套件全过。
- 真实上游实测：通过 `/v1/chat/completions` 发送一张写着 `47` 的图片，返回 `/* 47 */`。
- 同一测试也验证了 `kimi-k2.6-vl` 与 `Qwen3-VL-235B`。
- 约 1 MB 的 512×512 data URL 图片请求成功。

## Docker 镜像

已发布到 GitHub Container Registry，支持 `linux/amd64` 与 `linux/arm64`：

```bash
docker pull ghcr.io/ayeaaaa/mix2api:v1.0.3
docker pull ghcr.io/ayeaaaa/mix2api:latest
```

直接运行：

```bash
docker run -d --name mix2api -p 58675:58675 \
  -v "$PWD/data/accounts:/app/accounts" \
  -v "$PWD/data/usage:/app/usage" \
  ghcr.io/ayeaaaa/mix2api:v1.0.3
```

或用本包里的 `deploy/docker-compose.image.yml`：

```bash
cd deploy
docker compose -f docker-compose.image.yml up -d
```

## English summary

`mix2api` v1.0.3 adds image input for CodeArts vision models. OpenAI `image_url` parts, Responses `input_image` and Anthropic `image` blocks are normalized to CodeArts `image_url` content parts instead of being flattened to text; text-only messages keep their original plain-string shape. Base64 data URLs were verified against a real upstream (a `47` image returned `/* 47 */`), and a ~1 MB data URL was accepted. Remote URLs are passed through and depend on upstream fetching. The multi-arch image is published as `ghcr.io/ayeaaaa/mix2api:v1.0.3` and `:latest`.
