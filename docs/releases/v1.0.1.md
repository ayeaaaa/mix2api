# mix2api v1.0.1

v1.0.0 之后的补丁版：CodeArts 账号接入「账号代理槽」，并把 CodeArts 的出站传输对齐到 WorkBuddy 的 `wb_upstream_pool`。

## 这个版本做了什么

- **CodeArts 账号代理槽**：与 WorkBuddy 共用「设置 → 账号代理槽」，CodeArts 账号表新增「出口」下拉。聊天、模型发现、token 续期、签到和积分查询都走绑定的槽位；槽位 URL 变化自动跟随，槽位停用/删除回退直连，删除槽位自动解绑，重新登录保留绑定。
- **传输对齐**：CodeArts 出站改走 `wb_accounts.urlopen` / `wb_upstream_pool`，与 WorkBuddy 共用连接复用、代理认证、`no_proxy` 旁路和失效连接重试；`x-auth-token` 加入连接池身份字段，不同 CodeArts 账号不会共用同一条连接。
- **积分说明**：账户级剩余 / 总额 / 已用照常显示；单次请求的积分扣减上游不返回，最近请求表的 CodeArts 行积分显示 `0.00`、估算价格显示 `—`。
- **文档**：首页 README 同步代理槽、积分和传输说明；`deploy/docker-compose.image.yml` 指向本版本镜像。

## 升级

- 直接替换镜像或代码即可，无数据迁移；默认端口仍是 `58675`。
- 已有 CodeArts 账号不受影响；未绑定槽位时保持直连。
- 首次 OAuth 换取 token 仍直连（此时还没有账号可绑定）；绑定槽位后，账号级请求都走槽位。
- 代理槽按 HTTP/HTTPS 代理实现；SOCKS 槽位不适用。

## Docker 镜像

已发布到 GitHub Container Registry，支持 `linux/amd64` 与 `linux/arm64`：

```bash
docker pull ghcr.io/ayeaaaa/mix2api:v1.0.1
docker pull ghcr.io/ayeaaaa/mix2api:latest
```

直接运行：

```bash
docker run -d --name mix2api -p 58675:58675 \
  -v "$PWD/data/accounts:/app/accounts" \
  -v "$PWD/data/usage:/app/usage" \
  ghcr.io/ayeaaaa/mix2api:v1.0.1
```

或用本包里的 `deploy/docker-compose.image.yml`：

```bash
cd deploy
docker compose -f docker-compose.image.yml up -d
```

## English summary

`mix2api` v1.0.1 adds account-level proxy slots to the CodeArts realm and aligns CodeArts outbound traffic with the WorkBuddy transport (`wb_accounts.urlopen` / `wb_upstream_pool`): connection reuse, proxy authentication, `no_proxy` bypass and stale-connection retry. CodeArts accounts bind to the same slots as WorkBuddy accounts from the dashboard; disabling or deleting a slot falls back to direct, and re-login keeps the binding. No data migration is needed. The multi-arch image is published as `ghcr.io/ayeaaaa/mix2api:v1.0.1` and `:latest`.
