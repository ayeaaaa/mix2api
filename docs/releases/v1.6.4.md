# mix2api v1.6.3

小浣熊积分接入：账号余额、今日/近 7 天消耗和最近账单都能在看板查询。

## 这个版本做了什么

- **积分接口**：接入小浣熊网页端 `GET /api/web/points/v1/balance` 与 `GET /api/web/points/v2/bills?paging.limit=100&type=all`。
- **账号页显示**：小浣熊账号表新增「积分」列，显示可用积分、今日消耗和近 7 天消耗；出口卡片新增积分余额和今日消耗汇总。
- **刷新积分**：账号页新增「刷新积分」按钮，调用 `POST /raccoon/credits/refresh`，强制刷新余额与账单。
- **最近账单**：账号数据里保留最近 10 条账单摘要（事件名、积分、时间、类型、客户端类型），不包含账号 token 或上游内部账单 ID。
- **每请求积分**：每次请求完成后只认本次请求开始后新增、且尚未归因的账单，把账单 `points` 写入该请求 usage 行的 `credit`，与 WorkBuddy 的 credit 字段对齐；连续请求不会把上一笔账单算进来。`cost_policy` 仍为 `raccoon:unpriced`（积分不是 CNY 价格）。如果同一时间窗口内出现多条**新**账单（外部桌面端/网页端或并发请求），不猜测，`credit` 留空；账号总额、今日和近 7 天消耗仍精确。
- **WorkBuddy 兼容字段**：账号积分快照同时提供 `remain` / `amount` / `used`，单位 `points`；面板积分卡和账号卡可以复用同一套字段。
- **WorkBuddy 护栏**：预留积分、每日积分、每日 token、单模型每日 token 都作用于 Raccoon，使用全局限额值；账号表显示「限额」及原因，账号池选号时跳过被护栏拦下的账号。跨出口回退不适用于 Raccoon（模型目录不同）。
- **限制**：网页端 `type` 参数只接受 `all`；本版按 `all` 拉取最近账单再本地汇总。

## English summary

`mix2api` v1.6.3 adds Raccoon points. The provider now calls the web app's `/api/web/points/v1/balance` and `/api/web/points/v2/bills` endpoints, exposes the exact account balance plus today/7-day consumption derived from negative bill entries, and adds a "Refresh points" action. Each completed request also matches the newest bill in its request window and records that point cost in the usage row's `credit`, aligning with WorkBuddy; ambiguous windows leave credit empty, while `cost_policy` remains `raccoon:unpriced`. All 284 test suites pass; the multi-arch image is published as `ghcr.io/ayeaaaa/mix2api:v1.6.3` and `:latest`.
