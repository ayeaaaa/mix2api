# Upstream v1.10.4 Merge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Bring mix2api up to WorkBuddy upstream v1.10.4 (growth tasks, catalog/pricing refresh, model lists) without losing the mix2api UI, branding, CodeArts features, or release plumbing.

**Architecture:** mix2api is based on upstream v1.10.1 with custom CodeArts/UI work. Files that are byte-identical to upstream v1.10.1 are replaced with v1.10.4. Files with local changes get a targeted 3-way/manual port of only the upstream v1.10.4 hunks. The existing 246-suite test runner is the acceptance gate.

**Tech Stack:** Python 3 stdlib single-process gateway, HTML/JS dashboard, JSON pricing/catalog snapshots, custom test runner.

**Spec:** Upstream `937c179` (`v1.10.4`), diff `28527f4..937c179`.

## Global Constraints

- Keep default port `58675`, `/` new UI, `/classic` old UI.
- Keep mix2api branding and release version `1.1.3` until a separate release bump.
- Keep CodeArts vision/admin/scheduler features and all three exits.
- Do not overwrite `dashboard.html`, `wb_proxy.py`, `wb_scheduler.py`, or `wb_codearts.py` wholesale; only port upstream hunks.
- Preserve MIT attribution.

## Review Focus

- Growth task engine must not lose existing WorkBuddy daily check-in/travel behavior.
- Catalog curation must keep `deepseek-v4.1-flash-sg` when the plain name disappears.
- Model lists must include `gpt-6.1-sol`, `gpt-6-sol`, `gpt-6-luna`, `gemini-3.8-flash`, `kimi-k3.1-pro`, `minimax-m3.1-flash`.
- Non-chat models `hy-image-3.5` and `kling-video-v3` must stay out of chat model listings.
- CodeArts scheduler additions must remain after the upstream `run_travel` hunk is applied.
